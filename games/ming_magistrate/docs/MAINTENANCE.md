# 维护说明

## 文件与职责

直接维护根目录 `index.html`、`js/`、`css/`。游戏不使用模块加载器、联网判题、框架或构建步骤。

| js/data/scenes.js | 77个场景节点、21个谜题、词语解释、县境地点、后期调查与人物回应 |
| js/data/evidence.js | 原始材料全文，区分事件时间与文书制作时间 |
| js/data/people.js | 人物身份与只读动态小传 `personBiography(id, game, reading)` |

样式分为基础、布局、组件和场景四层。原图在本地保存于 `assets/originals/`，不随 Git 分发；运行仅加载已入库的 `assets/runtime/`。常规测试不要求原图；显式设置 `CHECK_SOURCE_ASSETS=1` 才执行原图审计。

## 场景与难度

主要循环：场景对白 → 获得本题少量材料 → 整理 → 出示 → 实际结果。前三案固定场景顺序，第四案开放三个已知地点。所有新节点必须有明确前情和眼前问题，不能依靠先读资料目录才能理解。

`sceneNodes` 顺序即主线，`sceneById`提供索引。`currentNode`可在第四案返回实际查访子场景。`sceneBeats`解析签收选择的条件回应。`advance`推进对白或结果，最后一段才进入下节点。人生及公务选择必须先回答，再读实际回应。

每个谜题通过 `kind` 选配对、排序或对照。规则只校验确定关系；界面不在放置时变色泄露正误。草稿分别保存 `placements`、`order` 或 `pair`。材料以 `sources`限定，`puzzleSources`过滤尚未取得的资料，提供适用的独立替代证明。

`submitPuzzle`错答停在原题、说明未对上的关系；正确后进入 `result`，确认结果再推进。首次对照题与查阅场景没有教学门槛，提示与查阅均为可选。`hint`只在请求时逐层增加，最多三层，不因错误次数自动解题。所有操作支持按钮与键盘，不要求拖拽。

## 第四案与复审

第四案 `autumn-explore`可访问账房、驿舍与米行，均可重访。原府卷由固定场景调取。`exploreReady`接受独立证明组合，不能改成必须按固定顺序扫完三个地点。原稿、账房说明与此前仓书去向记录可独立相互核对；驿路材料是另一条补强路径。

三轮复审依次处理旧亏、同次交付与责任。小游戏错误只重试。只有明确确认 `limitRound` 才记录本轮有限采信；`choose trade`同样必须带确认。三轮支持数决定完整、部分或失利，交易单列。不得把普通误答计入失败。

五处生活选择存于 `life`，每处等权，至少三次为官则走为官后日谈，否则著述。生活选择不改变材料、谜题、事实或裁定。阅读结局不修改存档或重复派奖。

## 当前存档

键：`jingshui.magistrate.v1`。格式：`version:3, contentRevision:"mystery-expanded.2", ruleset:"scene-mystery"`。只有一种可玩状态，不迁移、备份、归档、导出或展示旧进度。旧内容版本明确提示剧情更新，确认重新开始前保留原进度；已有有效进度的新开同样必须确认替换。

保存场景节点、已读段落、材料、事实、谜题草稿和完成状态、人物选择、五处倾向、三轮裁定、查访状态、地图视口及可选笔记。旧进度中的三个 `learn-*` 标记继续接受，新进度不生成、不要求这些标记，首题也不要求提示记录。校验检查节点前缀、材料发放、实际证据来源、题目答案与裁定一致性，不能只检查几个字段便接受结束状态。

字体大小18/20/22默认20，减少动态效果独立保存。保存失败持续提示，本局仍可继续。教学重看使用独立临时状态；退出恢复原游戏与查阅栈，不能覆盖当前存档。

## 阅读、导航与布局

只有一个原生dialog和明确页面栈，不叠加独立弹窗。push前保存父页位置与入口，返回恢复，关闭回到最初场景。Esc有父页时返回，否则关闭。案卷不放设置；帮助不重复案件资料。

文内释词由 `AnnotatedText({text, terms, used, onTerm, readingKey})` 渲染，返回文本节点与原生按钮；`Prose` 按空行分段并在同一展示内容内去重。普通字符串仍是正文来源，不写入HTML标记，不修改存档。默认只解释少量不常用称谓，`terms` 可限定词表，`used` 可跨段共用。场景、材料、前文回看与结局共用词义页；词义页在同一dialog内紧凑显示，保留逐层返回。

人物署名提供身份与“人物资料”标记；选择场景始终有“查看选项”按钮，定位选项并聚焦，不自动选择。画面快捷按钮置于实际画面网格内，不按估算的对白百分比定位。

`readingTextNodes` 遍历正文片段及词义按钮内的文本，供普通阅读器与富文本锚点共用。返回查阅时先设滚动距离作为后备，再由字符锚点恢复位置，不能反过来覆盖字号变化后的锚点。

正文与材料使用字符锚点，调字和连续缩放保留所读内容。地图图层使用完整3:2图的实际绘制坐标，HTML标签、SVG航线和图片共用世界坐标；地图不使用叙事背景的cover裁切。图上点选与地点列表同步，缩放和平移有按钮替代。

叙事图cover铺满场景框。开场与海瑞短会有横、竖独立构图；窄屏优先竖图。短横屏减少装饰，场景与对白左右分布，操作始终在阅读区外可达。不得通过整页缩小或裁掉控件伪造适配。

## 更新与动态效果

`app.js` 分别维护游戏画面和dialog的阅读观察器。push、back、close、字号和动态设置仅更新查阅层或样式；提示与私人笔记不重建背后的游戏。同背景推进复用已有figure，纸签与排序等游戏操作只更新所需内容，不启动场景过渡。窄屏或短横屏选中纸签后，底部操作区临时显示实际归属按钮与取消入口，完成归类后恢复提交区。

场景图与对白面板没有默认CSS入场动画。显式推进到不同背景或不同结局画面时，`prepareSceneTransition` 保留旧图，待新图解码后用220毫秒叠化。新图从透明到不透明，旧图全程留在下面，完成后清理。过期解码和动画由同一取消逻辑回收；同背景对白、查阅操作与窗口缩放不重播。按钮反馈独立于场景过渡。

游戏设置与系统 `prefers-reduced-motion` 任一开启即减少动态效果，运行中变化也立即取消当前过渡。`guidesDone` 和过渡任务只存界面内存，不写游戏存档。

## 素材与交付

人物小传按累计 `game.read` 的段落数、已证事实及实际选择更新。发放一组材料、进入某场景都不等于读完该场；新描写须在对应的话已经展示后开放。正文由身份、亲历与后续组成两三段，署名、人物索引及文书关联入口共用解析接口。回看用累计已读记录，不用当前段落倒推。结局已展示幕次的最高值只放 `ui.endingActRead`，返回上一幕不倒退，教学回放隔离；继续存档从结局首幕重新展示，未写进游戏存档，不改版本与判题。处分、调任、巡抚与著述分别随对应幕次开放，不能只凭 `verdict` 直接展示最终去向。

查阅窗口使用内容高度与窗口最大高度；宽度按 `library-页面类型` 设置行宽上限。正文为可收缩的内部滚动区，页头与确认操作保留在外层；不要恢复整页固定高度。人物头像使用实际参与排版的网格，窄屏放到文字上方。字体预览保留实际 18／20／22px，三档横排文字，手机改为三行按钮。地图正文有自身比例与高度上限，短横屏分栏，`ResizeObserver` 始终将地图世界拟合为3:2；小地图显示地点标记、当前选中名称与完整地点列表。字号、展开与自然缩放复用字符锚点及焦点键；未提交随手记属于临时UI状态，弹窗往返不会清空。

当前保留41份PNG及对应运行WebP（含历轮横竖分镜与v1.2廊下图），实际清单见 `docs/asset-manifest.json`。前轮清稿见 `assets/INK-CLEANUP.md`，人物与动作对应见 `assets/SCENE-IDENTITY.md`。不使用全局提亮、模糊或滤镜代替局部笔墨整理。

图像精确日期、数量、封号及路线均由HTML/SVG呈现，不把绘画当证据。主角统一规则和生成提示见 `assets/MYSTERY.md`。人物与背景保持同一写意程度，不留局部写实脸、密绣纹或材质贴图；夜景、阴雨和室内分别安排明暗，不能统一抬亮。县衙各图对照围墙、门、树、廊柱与地面，横竖图独立构图且保留合理距离。已删除旧玩法专用素材和被替代的人物旧图，继续保留所有在用原图。

`python3 tools/prepare_assets.py` 压缩原图并重写尺寸和校验清单。GitHub Pages 直接加载仓库中的源码与运行资源。删除素材前核对场景、结局、CSS与舆图引用。

## 人物与场景对应

人物姓名只存姓名。同名吴长生的住处放在 `role`，独立材料链接及回看用 `personCaption` 同时给出姓名与身份；不把田号、缴欠结论挂到姓名旁。匿名人物保留船工、许家账房等称谓。人物入口的焦点键使用人物ID，不能以同名文本作唯一标识。小头像逐人配置脸型、发式、衣着和姿态，配置全集应与22位人物ID完全一致，禁止静默回退成通用村民；多人卡片、详情与晚年小传共用头像接口。

场景先核人物、地点、时节与正在做的事，再选择分镜。`art-data.js` 对新分镜记录 `cast`、`setting`、`action`，不参与判题或显示线索。不能把秋娘的递状图改个标题就给吴长生使用；同地点延续建筑、光源和角色面貌，人物站位、主角手势及旁人动作按事件安排。文书查访可用案头与信笺画面，不能错用夜泊卸粮图。结局执行不再出现已判徒的许慎行。

## v1.1 条件材料与声音

选择项可声明 grant，由 engine.js 在选择成立时发放，沿用 documents 的 via/acquired 出处；storage.js 将已选分支发放纳入允许与必需集合，并核对 answers/choices 一致性。常规调卷提供独立汇合点。内容版本不匹配时 readSave 返回 replaceRequired，标题开始须进入替换确认，确认前不写存档。

scene.ambience 控制环境声，beat.cue 控制首次呈现动作声；渲染只作声音呈现，不判题。app 内存集合避免同段重播，不写存档。sound.setScene 的同场景调用幂等；关闭声音或切后台停止环境源。合成和生命周期在 audio.js。素材及提示集见 ../assets/SUSPENSE-REVISION.md。教学回放在 tutorial-order 结果结束，不将正式第一案称作教程。

验收新增81种支线选择组合，均保留完整翻案；原有150条混合流程和六种查访顺序仍验证。规则现覆盖二十一题，涉及的新浏览器检查见 tests/expansion-browser.py。

## v1.2 剧情与结果呈现

77节点、21题、64材料；第一案18节点（两引子题与三正式题），第二案五题。三处早期地图过场并入查访，scene.visitPlaces在进入场景时记录实际到达；已知地点仍由places登记，舆图仍可查阅。

谜题可选 resultSpeaker、resultReaction:{speaker,text}；正确提交由引擎复制反应到 feedback.reaction，读取存档不重算反应。有限裁定无成功反应，主审发言；第三轮保留前轮缺口的特殊文本。反应、结论共用阅读区、各有署名，一次继续；阅读锚点也包含反应正文。

scene beat.art可指定同场景分镜，显式推进／回退时沿用现有叠化，同图复用不重播。

scene beat.choiceEcho按已选choices读取只读sideConsequences，结案读取，结局另写之后的回声，避免逐字重复；不改变事实、发放或判题。boat_recheck仅boat-side的ledger取得，family_letter仅relief-side的neighbours取得。其余分支有完整独立原据，不强制收集摘录。

内容版本为mystery-expanded.2，version仍3。旧内容提示重开，确认前不写入；不迁移。新增庭审节点后维护人物小传已读门槛，不能凭材料发放提前开放证言或结局。
